# UI程式必須注意指引

紀錄日期：2026-11-13（Asia/Taipei）

本文件供開發者與 AI 在修改表單 UI 前閱讀，避免再次出現報價單單位欄位的選單過窄、箭頭消失與邊框被遮住問題。根目錄 `AGENTS.md` 已要求相關修改遵循本文件。

## 使用者要求

- 報價單的單位欄位可手動輸入，也可選取「片、kg、批、式」。
- 欄位右側顯示可點選的三角箭頭，外觀參照「計稅方式」。
- 下拉清單展開時與整個欄位同寬，不是只在右側箭頭的小區塊下方展開。
- 新增報價單、編輯既有明細及動態新增明細列使用相同操作方式。
- 外框完整、箭頭清楚，輸入文字不能遮住箭頭或底部邊框。

## 曾經發生的問題

### 一、將原生 select 縮成箭頭按鈕

最初將 select 設為 `width: 2rem`，放在輸入框右側。原生選單的展開寬度受 select 本體寬度影響，導致選項清單狹窄，與使用者要求的完整欄位下拉樣式不同。

修正方向：select 保持欄位全寬；手動輸入區僅覆蓋左側文字區，右側留出箭頭空間。不要再次將 select 本體縮成只有箭頭寬度。

### 二、重疊輸入框遮住箭頭與底部外框

select 改為全寬後，在上方疊加 input。input 雖然設定了寬高，仍受其他 CSS 最小尺寸影響：

- `wwwroot/css/site.css` 的 `.quotation-lines .form-control` 設有 `min-width: 62px`。
- 舊的 `.quotation-unit-picker > input` 優先順序低於上述規則，其 `min-width: 0` 未生效。
- Bootstrap 的 `.form-control-sm` 另有 `min-height`。只設定 `height`，不代表能小於 `min-height`。
- 疊在上層的 input 因此可能大於預留文字區，遮住右側箭頭和底部邊框，看起來像欄位局部消失。

核心教訓：**宣告 width、height 不等於實際尺寸；必須同時檢查 min-width、min-height、padding、box-sizing 及 CSS 優先順序。**

## 目前修正方式與程式位置

檔案：`SmartIMS.Web/Views/Quotation/Edit.cshtml`。

- `.quotation-unit-picker`：定位容器，最小寬度為 75px。
- `.quotation-unit-picker > select`：維持 `width: 100%`，提供完整外框、原生箭頭與全寬選單。
- `.quotation-lines .quotation-unit-picker > input`：提高局部規則優先順序，將輸入區限於左側。
- input 設定 `width`、`max-width: calc(100% - 2rem)`，保留右側箭頭操作空間。
- input 設定 `min-width: 0`、`min-height: 0`、`box-sizing: border-box`；寬高限制不可省略。
- input 的 `top`、`left` 為 1px，`height: calc(100% - 2px)`，避免蓋住 select 外框。
- `prepareUnitPicker()`：處理既有明細與動態新增明細；重複呼叫不得重複包裝。
- select 不承擔送出值；選取後更新具備 `Lines[index].Unit` 名稱的 input，觸發 input/change 事件，保留手動輸入與原有儲存流程。

上述數值是目前實作，不是所有畫面的通用常數。更換字級、主題、Bootstrap 版本或表格尺寸時，應重新確認實際尺寸。

## 後續修改流程

1. 先確認使用者參考圖的外觀與互動要求，不能只做到「有選項」。
2. 同時閱讀 Razor 局部樣式、全域 `site.css`、Bootstrap 規則及動態建立控制項的 JavaScript。
3. 在瀏覽器查看 computed styles 與實際元素邊界；確認是哪條規則生效，而非只看原始 CSS 宣告。
4. 優先修正具體衝突，不以大量 `!important`、裁切外框或停用控制項掩蓋問題。
5. 修改後執行建置，並進行下方 UI 驗收；必要時使用獨立預覽，避免重整或覆寫使用者尚未儲存的報價單。
6. 使用者要求部署時，依部署流程更新 IIS，並區分部署校驗與 UI 驗收結果。

## UI 驗收項目

- 空白、已選單位、自訂文字三種狀態，四邊外框均完整。
- 未聚焦與聚焦時，文字、箭頭及外框不互相遮蔽。
- 點擊箭頭能開啟選單；選項為「片、kg、批、式」，清單至少與欄位同寬。
- 選取後欄位顯示正確，仍可輸入自訂單位；儲存後重新讀取保留原值。
- Tab 可進入輸入區與選單；原生鍵盤選單操作正常。
- 既有明細、動態新增明細、複製後明細均正常，項次重新編排不影響單位值。
- 唯讀或無編輯權限狀態不可透過下拉箭頭修改。
- 窄欄位、較小視窗及常用縮放比例（例如 100%、125%）下，箭頭與邊框仍可辨識。
- 修改其他欄位或增刪明細不受影響。
